\section{Introduction}
%==============================================================================

This document provides a comprehensive overview of all user stories implemented in the TeeTime Golf App. Each story includes the implementation status, technical details (APIs, database tables), and business logic explanations for client comprehension.

\textbf{All features listed in this document are fully implemented and tested.}

\section{Profile \& User Management}
%==============================================================================

\subsection{US-01: View and Edit Profile}
\implemented

\textbf{Story:} I want the ability to view and edit my profile including past game scores, handicap, club memberships, phone number, and location, so that my information stays current.

\textbf{Implementation:}
\begin{itemize}[leftmargin=*]
  \item \textbf{API Endpoints:}
    \begin{itemize}
      \item \texttt{GET /api/profile} --- Retrieve current user profile
      \item \texttt{PUT /api/profile} --- Update profile fields
    \end{itemize}
  \item \textbf{Database Tables:} \texttt{users}, \texttt{user\_profiles}, \texttt{game\_scores}, \texttt{user\_club\_memberships}
  \item \textbf{Editable Fields:} First/last name, phone, email, handicap, bio, location, home course, equipment (driver, irons, putter, ball), preferences (walk/ride, preferred tee time)
  \item \textbf{Logic:} Profile data split between \texttt{users} (auth info) and \texttt{user\_profiles} (golf-specific data). Updates trigger \texttt{updated\_at} timestamp via database trigger.
\end{itemize}

\subsection{US-02: Social Rate Score and History}
\implemented

\textbf{Story:} I want the ability to view my Social Rate score and history, so that I can track my reliability reputation.

\textbf{Implementation:}
\begin{itemize}[leftmargin=*]
  \item \textbf{API Endpoints:}
    \begin{itemize}
      \item \texttt{GET /api/social-rate} --- Get current score and stats
      \item \texttt{GET /api/social-rate/history} --- Get detailed change history
    \end{itemize}
  \item \textbf{Database:} \texttt{user\_profiles.social\_rate} (integer 0-100), \texttt{social\_rate\_logs}
  \item \textbf{Scoring Logic:}
    \begin{itemize}
      \item Starting score: 100 points (no upper limit)
      \item Invite accepted: +2 points
      \item Decline $>$24 hours before: -1 point
      \item Cancel $<$24 hours before: -5 points
      \item No-show: -10 points
      \item Minimum score: 0
    \end{itemize}
  \item \textbf{Audit Trail:} Every change logged with previous score, delta, new score, reason, and tee time reference
\end{itemize}

\subsection{US-03: Generate Personal QR Code (Get Drafted)}
\implemented

\textbf{Story:} I want the ability to generate my personal QR code ("Get Drafted"), so that others can easily add me to their On-Deck list.

\textbf{Implementation:}
\begin{itemize}[leftmargin=*]
  \item \textbf{API Endpoints:}
    \begin{itemize}
      \item \texttt{GET /api/draft/qr} --- Get or generate QR code
      \item \texttt{POST /api/draft/qr/regenerate} --- Invalidate old codes and create new
    \end{itemize}
  \item \textbf{Database:} \texttt{draft\_qr\_codes} (code\_hash, version, is\_active, scanned\_count)
  \item \textbf{Logic:}
    \begin{itemize}
      \item QR payload contains: version, userId, random code, HMAC signature
      \item Code is hashed (SHA-256) before storage --- actual code never stored
      \item Regeneration revokes all previous codes
      \item Tracks scan count and last scanned timestamp
    \end{itemize}
  \item \textbf{Frontend:} Uses \texttt{react-native-qrcode-svg} library, 260px size for reliable scanning
\end{itemize}

\subsection{US-04: Scan QR Code (Scan to Draft)}
\implemented

\textbf{Story:} I want the ability to scan another user's QR code ("Scan to Draft") and confirmation, so that I can quickly add them to my On-Deck.

\textbf{Implementation:}
\begin{itemize}[leftmargin=*]
  \item \textbf{API Endpoints:}
    \begin{itemize}
      \item \texttt{POST /api/draft/scan} --- Validate QR and get user preview
      \item \texttt{POST /api/draft/confirm} --- Confirm adding to On-Deck
      \item \texttt{GET /api/draft/history} --- View who scanned your code
    \end{itemize}
  \item \textbf{Database:} \texttt{qr\_scan\_history} (tracks scanner, scanned user, timestamp, was\_added)
  \item \textbf{Validation:}
    \begin{itemize}
      \item Verify HMAC signature matches
      \item Check code is active and not revoked
      \item Prevent self-scanning
      \item Check if already in roster
    \end{itemize}
  \item \textbf{Frontend:} Uses \texttt{expo-camera} with barcode scanning, 2-second cooldown between scans, animated scan line overlay
\end{itemize}

\subsection{US-05: Complete Tee Time History}
\implemented

\textbf{Story:} I want the ability to view my complete tee time history (past and upcoming), so that I can track my golf activity.

\textbf{Implementation:}
\begin{itemize}[leftmargin=*]
  \item \textbf{API:} \texttt{GET /api/tee-times/history?filter=<status>}
  \item \textbf{Filters:} all, upcoming, completed, cancelled, no\_show
  \item \textbf{Response Data:} Course name, date/time, status, user role (organizer/participant), attendance status, game score, participant count
  \item \textbf{Logic:} Combines tee times where user is creator OR participant, sorted by date descending
\end{itemize}

\subsection{US-10: Create and Maintain Multiple Rosters}
\implemented

\textbf{Story:} I want the ability to create and maintain multiple rosters of golf buddies, so that I can organize my regular playing partners into selectable groups.

\textbf{Implementation:}
\begin{itemize}[leftmargin=*]
  \item \textbf{API Endpoints:}
    \begin{itemize}
      \item \texttt{GET /api/roster/groups} --- List all groups
      \item \texttt{POST /api/roster/groups} --- Create new group
      \item \texttt{PUT /api/roster/groups/:id} --- Update group
      \item \texttt{DELETE /api/roster/groups/:id} --- Delete group
    \end{itemize}
  \item \textbf{Database:} \texttt{roster\_groups}, \texttt{roster\_group\_members}
  \item \textbf{Group Properties:} name, description, color (hex), icon, auto\_invite flag, max\_members, sort\_preference
  \item \textbf{Logic:} Many-to-many relationship allows members to belong to multiple groups
\end{itemize}

\subsection{US-11: Drag-and-Drop Between Roster and On-Deck}
\implemented

\textbf{Story:} I want the ability to drag-and-drop golfers between "Roster" and "On Deck" sections, so that I can prioritize my preferred playing partners.

\textbf{Implementation:}
\begin{itemize}[leftmargin=*]
  \item \textbf{API Endpoints:}
    \begin{itemize}
      \item \texttt{PUT /api/roster/reorder} --- Update positions after drag
      \item \texttt{PUT /api/roster/:id/move} --- Move between sections
    \end{itemize}
  \item \textbf{Database:} \texttt{roster.position} (integer), \texttt{roster.is\_on\_deck} (boolean)
  \item \textbf{Definitions:}
    \begin{itemize}
      \item \textbf{Roster:} Players who will be auto-invited (is\_on\_deck = false)
      \item \textbf{On-Deck:} Reserve players manually selected when roster fails to fill (is\_on\_deck = true)
    \end{itemize}
  \item \textbf{Frontend:} React Native Draggable FlatList with smooth animations
\end{itemize}

\subsection{US-12: Sort Roster by Multiple Criteria}
\implemented

\textbf{Story:} I want the ability to sort my roster by Social Rate, Distance to Course, Handicap, or Club Membership, so that I can make strategic invite decisions.

\textbf{Implementation:}
\begin{itemize}[leftmargin=*]
  \item \textbf{API:} \texttt{GET /api/roster?sortBy=<option>}
  \item \textbf{Sort Options:}

      \item \texttt{socialRate} --- Reliability score (descending)
      \item \texttt{handicap} --- Skill level (ascending)

  \item \textbf{Logic:} Dynamic SQL ORDER BY based on parameter
\end{itemize}

\subsection{US-24: On-Deck Selection When Roster Fails}

\textbf{Implementation:}
\begin{itemize}[leftmargin=*]
  \item \textbf{Service:} \texttt{fcfsDeadlineService.js} (cron job)
  \item \textbf{Trigger:} When all roster invites expire/decline and spots remain unfilled
  \item \textbf{Notification:} "Your tee time has unfilled spots. Select from On-Deck?"
  \item \textbf{API:} \texttt{POST /api/tee-times/:id/on-deck-invites}

\subsection{US-25: Create FCFS Invite}
\implemented

\textbf{Story:} I want the ability to create a First Come First Served invite by selecting date, time, course (with autocomplete), and group size (2/3/4), so that I can quickly organize my round.

\textbf{Implementation:}
\begin{itemize}[leftmargin=*]
  \item \textbf{API:} \texttt{POST /api/invites} with \texttt{inviteType: 'fcfs'}
  \item \textbf{Logic:}
    \begin{itemize}
      \item All invitees notified simultaneously
      \item First to accept gets confirmed spot
      \item When full, remaining invites moved to waitlist
      \item Atomic acceptance prevents race conditions
    \end{itemize}
\end{itemize}

\subsection{US-26: FCFS Broadcast to Entire Roster}
\implemented

\textbf{Story:} I want the ability to create a First Come First Serve invite that broadcasts to my entire roster, so that I can quickly fill spots for spontaneous rounds.

\textbf{Implementation:}
\begin{itemize}[leftmargin=*]
  \item \textbf{API:} \texttt{POST /api/invites/from-roster} with \texttt{teeTimeId}
  \item \textbf{Logic:} Fetches all roster members (excluding On-Deck) and creates FCFS invites for all
  \item \textbf{UI:} "Invite Entire Roster" button in FCFS creation flow
\end{itemize}

\subsection{US-27: First Responder Confirmation with Tie-Breaker}
\implemented

\textbf{Story:} I want the ability to see who responds first and is automatically confirmed, so that spots are filled efficiently. If we need to determine tie-breaker criteria, the person who is higher in my roster should get priority.

\textbf{Implementation:}
\begin{itemize}[leftmargin=*]
  \item \textbf{Repository:} \texttt{inviteRepository.acceptInviteAtomic()}
  \item \textbf{Tie-Breaker Logic:}
    \begin{itemize}
      \item 500ms delay to collect near-simultaneous accepts
      \item Database row locking: \texttt{SELECT ... FOR UPDATE}
      \item For FCFS: Roster position determines priority
      \item For Roster invites: Invite position (order invited) determines priority
      \item Lower position number = higher priority
      \item Winner added as participant; loser moved to waitlist
    \end{itemize}
  \item \textbf{Transaction:} Entire operation in single database transaction for atomicity
\end{itemize}

\subsection{US-28: FCFS Response Deadline}
\implemented

\textbf{Story:} I want the ability to set a deadline for FCFS responses, so that I can finalize plans by a certain time.

\textbf{Implementation:}

  \item \textbf{API:} \texttt{POST /api/tee-times/:id/fcfs-deadline}
  \item \textbf{Quick Presets:} 2 minutes, 5 minutes, 1 hour, 24 hours
  \item \textbf{Logic:} Updates \texttt{expires\_at} for all pending invites on the tee time
  \item \textbf{Expiration:} Cron job marks expired invites and notifies organizer
\end{itemize}

\subsection{US-29: Notification When Tee Time Not Filled}
\implemented

\textbf{Story:} I want the ability to have the app notify me if my tee time is not filled by the expiration date, and prompt me to select from my on-deck to fill.

\textbf{Implementation:}
\begin{itemize}[leftmargin=*]

  \item \textbf{Check Logic:}
    \begin{itemize}
      \item Runs periodically (cron)
      \item Finds tee times with expired invites and unfilled spots
      \item Checks tee time status is 'pending' or 'open'
    \end{itemize}
  \item \textbf{Notification:} Push notification to organizer with action to select On-Deck players
  \item \textbf{On-Deck Flow:} Selected players receive FCFS invites
\end{itemize}

\section{Technical Architecture Summary}
%==============================================================================

\subsection{Database Schema}

The application uses PostgreSQL with 32 tables organized into logical groups:

\begin{itemize}[leftmargin=*]
  \item \textbf{Core Tables:} users, user\_profiles, devices, sessions, otp\_requests, magic\_links
  \item \textbf{Social/Roster:} roster, roster\_groups, roster\_group\_members, friendships, friend\_requests, blocked\_users
  \item \textbf{Tee Times:} tee\_times, tee\_time\_participants, invites, invite\_responses
  \item \textbf{Accountability:} social\_rate\_logs, tee\_time\_attendance
  \item \textbf{Supporting:} notifications, golf\_courses, draft\_qr\_codes, qr\_scan\_history
\end{itemize}

\subsection{Key Business Logic Components}

\begin{itemize}[leftmargin=*]
  \item \textbf{Atomic Invite Acceptance:} Database row locking with 500ms delay for tie-breaker resolution
  \item \textbf{Social Rate System:} Automatic penalty/reward calculation with full audit trail
  \item \textbf{QR Code Security:} HMAC-signed payloads, hashed storage, revocation support
  \item \textbf{Invite Expiration:} Cron-based monitoring with automatic status updates and notifications
  \item \textbf{Attendance Tracking:} Pre-tee time reminders, one-tap check-in, no-show penalty automation
\end{itemize}

\subsection{API Structure}

All APIs follow RESTful conventions:
\begin{itemize}[leftmargin=*]
  \item \textbf{Authentication:} JWT tokens with automatic refresh
  \item \textbf{Base URL:} \texttt{/api/}
  \item \textbf{Modules:} auth, profile, roster, tee-times, invites, friends, notifications, courses, social-rate, attendance, draft
\end{itemize}
